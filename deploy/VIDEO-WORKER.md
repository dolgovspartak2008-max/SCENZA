# Запуск обработки видео SCENZA

SCENZA развёрнута на `https://scenza.2.27.10.27.sslip.io`. Активный релиз: `/srv/scenza/releases/20260914-gpt56-luna`, рабочая ссылка `/srv/scenza/current`. Сервисы `scenza` и `scenza-worker` включены в автозапуск. Supabase-миграция видеообработки применена.

API (`server/index.mjs` либо `server/production.mjs`) принимает загрузки и сохраняет задания. Отдельный процесс `server/ai/worker.mjs` выполняет FFmpeg, Whisper, поиск сцен, GPT-5.6 Luna и рендер. Закрытие браузера не останавливает сохранённое задание, пока API, worker и хранилище работают.

## Окружение

- Node.js 24 LTS: локальная очередь использует встроенный `node:sqlite`; проверено на Node 24.19.0.
- Python 3.12: проверено на 3.12.14. FFmpeg и ffprobe уже входят в зависимости проекта (`ffmpeg-static`, `ffprobe-static`).
- Постоянный диск для исходников, моделей, прокси и результатов; исходник может занимать до 20 GiB, временные копии требуют дополнительного места.
- Доступ worker к OpenAI API и к загрузке модели Whisper при первом запуске. Все секреты остаются на сервере.

Для новой рабочей копии установите Node-зависимости по имеющемуся lock-файлу командой `pnpm install --frozen-lockfile`. В копии с установленными зависимостями повторная установка не нужна.

Создайте отдельное Python-окружение в корне проекта. Команда `python` должна указывать на установленный Python 3.12:

```powershell
python -m venv .scena/venv
.scena/venv/Scripts/python.exe -m pip install -r server/ai/requirements.txt
```

Linux:

```sh
python3.12 -m venv .scena/venv
.scena/venv/bin/python -m pip install -r server/ai/requirements.txt
```

Используются faster-whisper 1.2.1, PySceneDetect 0.6.7.1 и OpenCV headless 4.12.0.88. Модель Whisper по умолчанию — `small`, устройство — CPU, вычисления — int8. Первое распознавание скачивает модель. На проверенном русском видео `small` дала более понятный текст, чем `base`; имена могут распознаваться с ошибками. `SCENZA_WHISPER_MODEL`, `SCENZA_WHISPER_DEVICE`, `SCENZA_WHISPER_COMPUTE_TYPE` меняют эти параметры; GPU требует отдельно подготовленного совместимого окружения и здесь не проверялся.

## Настройки

Используйте `.env.example` как шаблон `.env`, не перезаписывая существующие секреты. Сам `.env` не входит в Git.

| Параметр | Назначение |
| --- | --- |
| `SCENA_DATA_DIR` | Одинаковый постоянный абсолютный каталог API и worker на сервере. В локальном примере — `.scena`. |
| `OPENAI_API_KEY` | Серверный ключ OpenAI для анализа моментов и интерпретации текстовых правок. На сервере хранится только в `/srv/scenza/shared/ai.env`, права `0600`, владелец `scenza`. |
| `OPENAI_MODEL` | `gpt-5.6-luna`. Анализ и текстовые правки используют одну модель; автоматического перехода на Gemini нет. |
| `SUPABASE_URL`, `SUPABASE_SECRET_KEY` | Вместе включают Supabase вместо локальной SQLite-очереди. Секретный ключ нужен только серверу. |
| `SUPABASE_PUBLISHABLE_KEY` | Дополнительно требуется существующему `server/production.mjs` для аккаунтов. |
| `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | Все четыре включают S3-совместимое объектное хранилище. Endpoint — HTTPS origin без пути bucket. |
| `S3_REGION` | Регион подписи S3; default `auto`, укажите регион своего провайдера при необходимости. |
| `SCENZA_PYTHON` | Полный путь Python worker; без значения используется проектное `.scena/venv`. |
| `SCENZA_WHISPER_CACHE`, `HF_HOME` | Каталоги модели и служебного кэша. Для сервиса задайте существующие доступные для записи постоянные пути. |

Если обе Supabase-переменные пусты, видеоочередь создаёт `SCENA_DATA_DIR/ai/video-jobs.sqlite` автоматически; SQL-миграция локально не нужна. Если четыре обязательные S3-переменные пусты, файлы хранятся в `SCENA_DATA_DIR/ai/objects`. Частичное заполнение конфигурации хранилищ приводит к ошибке.

Перед включением облачной очереди вручную примените `server/ai/migration.sql` в выбранном Supabase-проекте. Скрипт создаёт таблицы видео, функции очереди и ограничения доступа. Он не выполняется автоматически; данная инструкция не означает, что миграция уже применена. Существующая схема аккаунтов из `server/supabase.sql` обслуживает отдельную часть приложения.

## Локальный запуск

В двух терминалах из корня проекта запустите API и worker с одним env-файлом:

```sh
node --env-file=.env server/index.mjs
```

```sh
node --env-file=.env server/ai/worker.mjs
```

Если переменные уже переданы окружением, `--env-file=.env` можно опустить. Worker автоматически опрашивает сохранённую очередь. Без `GEMINI_API_KEY` загрузка и подготовка видео доступны, AI-анализ сообщает о необходимости подключения; фиктивные кандидаты не создаются.

Для отдельного frontend-процесса используйте `node node_modules/vite/bin/vite.js`. Альтернатива для разработки: `pnpm dev` читает существующий `.env` и запускает API, Vite и worker вместе. При таком запуске второй worker не нужен. Не запускайте одновременно этот dev launcher и второй экземпляр API на том же порту.

## Сервер

API можно запускать через существующий `server/production.mjs`; он дополнительно требует `SCENA_PUBLIC_ORIGIN` с HTTPS, `SUPABASE_URL`, `SUPABASE_SECRET_KEY` и `SUPABASE_PUBLISHABLE_KEY`. Worker остаётся отдельным постоянным процессом:

```sh
node --env-file=.env server/production.mjs
node --env-file=.env server/ai/worker.mjs
```

На платном сервере используются `deploy/scenza.service` для API и ботов и `deploy/scenza-worker.service` для обработки видео. Оба читают `/srv/scenza/shared/production.env` и `/srv/scenza/shared/ai.env`; секреты находятся вне web-root, дополнительный env доступен только пользователю сервиса. Python установлен в `/srv/scenza/shared/venv`, модели — в `/srv/scenza/shared/models`. Worker ограничен 5 ГБ памяти и CPU 300%, автоматически перезапускается после сбоя.

Проверка: `systemctl status scenza scenza-worker`. Релиз непосредственно перед Luna сохранён в `/srv/scenza/releases/20260914-bottom-subtitles`; прежнее окружение — в `/srv/scenza/shared/deploy-backups/20260914-gpt56-luna/ai.env`. Также сохранены версия до внедрения AI `/srv/scenza/releases/20260913-1442-auth-complete` и исходный API-unit в `/srv/scenza/shared/deploy-backups/20260913-ai-connected`.

При временном тайм-ауте Supabase worker повторяет подключение без завершения процесса. Повторное получение задачи тем же worker возвращает его незавершённую аренду, сохраняя прогресс и счётчик попыток.

API и worker должны видеть один каталог `SCENA_DATA_DIR/ai/uploads`: worker забирает оттуда загруженный исходник до переноса в объектное хранилище. Это требование сохраняется и при S3. Разделение на разные хосты без общего файлового тома сейчас не поддержано. SQLite подходит для процессов на одном хосте; для нескольких хостов используйте Supabase и отдельно обеспечьте общий upload-каталог.

Не запускайте FFmpeg/Whisper в Vercel Functions или похожем короткоживущем serverless-обработчике: worker выполняет длительные процессы и работает с постоянными файлами. Публикация сайта, настройка службы, домена и reverse proxy выполняются отдельно; эти файлы их не меняют.

## Проверка и границы

GPT-5.6 Luna подключена к API и постоянному systemd-worker через закрытое серверное окружение. После публикации полный цикл с настоящими Supabase и Luna завершился успешно: подготовка видео, два прохода анализа, предпросмотр, текстовая правка размера/цвета/слов субтитров и экспорт H.264 1080×1920. На 23,35-секундном исходнике получен ролик 8,88 секунды. Предыдущий релиз сохранён для отката.

```sh
node --test tests/media-pipeline.test.mjs tests/gemini.test.mjs tests/ai-storage.test.mjs tests/video-pipeline.test.mjs
```

Реальный локальный анализ Windows (на Linux замените путь Python):

```powershell
.scena/venv/Scripts/python.exe server/ai/media.py analyze --input public/videos/platform-example-5958.mp4 --output .scena/media-check/analyze.json
.scena/venv/Scripts/python.exe -m pip check
```

`analyze.json` содержит язык, сегменты и слова с временными метками, границы сцен и нормализованные положения лиц/кадра. При отсутствии зависимостей или ошибке распознавания CLI возвращает ненулевой exit code и JSON ошибки в stderr.

Фактические ограничения реализации:

- Luna использует два прохода: обзор всей части видео (до 200 кадров), затем подробную проверку выбранных моментов (до 240 кадров). В OpenAI передаются кадры и расшифровка с таймкодами; исходный звук напрямую модель не получает.

- MP4/MOV/MKV/WebM/M4V до 20 GiB; загрузка последовательными чанками по 8 MiB. Видео — до 12 часов и до 8192 пикселей по каждой стороне.
- Прокси для анализа — до 640 пикселей по ширине, 2 fps; адаптер Luna принимает локальный прокси до 2 GiB и отправляет в OpenAI только выбранные JPEG-кадры, расшифровку и границы сцен. Ответ модели содержит максимум 15 кандидатов; каждый клип — до 120 секунд. Меньшее число кандидатов допустимо.
- Видео длиннее 30 минут анализируются окнами с перекрытием в 2 минуты. Результат каждого окна сохраняется; повтор продолжает незавершённую часть. Таймкоды возвращаются на исходную шкалу, повторяющиеся моменты объединяются, в интерфейс попадают до 15 лучших кандидатов. Покрытие двухчасовой шкалы проверено тестами; реальный многочасовой фильм пока не проверен.
- Текстовые правки могут заменять ошибочные слова в субтитрах. Замены сохраняются с версией ролика, не изменяют исходную расшифровку и тайминги слов.
- Один worker обрабатывает одно задание одновременно. Очередь сохраняется между запусками; просроченная аренда задания допускает повтор, после трёх прерванных попыток появляется ошибка.
- Кадрирование использует выборочные фронтальные лица и сглаживание, не идентифицирует говорящего. Распознавание речи может ошибаться; субтитры и выбранный фрагмент следует просмотреть до экспорта.
- Оригиналы сохраняются (`keep-original`); автоматическая политика удаления и квоты диска сейчас не настроены. Нагрузочная проверка файлов максимального размера и многочасовых видео не выполнена.
- Прямые публичные HTTP(S)-ссылки поддерживаются с проверкой адресов и перенаправлений. Страницы YouTube и закрытые видеосервисы в новом AI-маршруте не скачиваются: интерфейс предлагает файл или прямую ссылку.
- S3/R2: файлы больше 64 MiB передаются потоковыми частями по 64 MiB. При ошибке выполняется abort; повтор после перезапуска worker начинает объект заново. Контракт проверен с HTTP-подменой и файлом 65 MiB, живой сервис ещё не подключён.
- Музыка — загружаемые пользователем треки с выбором вручную и ducking. Предустановленная лицензированная коллекция и AI-подбор по настроению ещё не добавлены. Автоматическое размещение рекламы учитывает найденные лица и субтитры; OCR исходного текста и распознавание всех значимых объектов не реализованы.
- До перехода на Luna живая проверка основного маршрута использовала настоящее видео 23,35 секунды, настоящий Gemini, текстовую правку, баннер и рендер H.264/AAC 1080×1920. При перегрузке основной модели запрос успешно выполнила резервная Gemini 3.5 Flash. Автоматические unit/integration-тесты отдельно подменяют ответ AI, чтобы не расходовать квоту при каждом запуске.
- Для явного живого теста: `node --env-file=.env tests/ai-live.mjs`. Он обращается к GPT-5.6 Luna и сохраняет результаты в отдельную папку `.scena/live-check`. Повтор поддерживает `SCENZA_LIVE_RESUME_DIR` и `SCENZA_LIVE_PROJECT_ID`, чтобы использовать сохранённый анализ.
- До перехода на Luna полный цикл с настоящими Supabase и Gemini был проверен на платном сервере: получен MP4 H.264/AAC 1080×1920. Отдельная задача успешно выполнена постоянным systemd-worker. Полнометражные фильмы и максимальные размеры загрузок ещё не проверены. S3 не подключён: файлы хранятся на постоянном диске сервера, метаданные и очередь — в Supabase.
